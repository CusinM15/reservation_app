## A. Naročilo VPS pri Contabu

1. https://contabo.com → **Sign Up** (Company za šolo/DDV, ali Personal).
2. **Cloud VPS 4** → izberi:
   - **Location: Germany** (EU/GDPR),
   - **Image: Ubuntu 24.04 LTS**,
   - **SSH key**: prilepi svoj javni ključ (`ssh-ed25519 …` / `ssh-rsa …`),
   - opcijsko: dodaj **Storage Extension** (če rabiš več diska).
3. Zaključi nakup; **root geslo** in IP dobiš po e-pošti. Zabeleži IP.

## B. Prva prijava in utrditev

```bash
ssh root@<IP>

# 1) posodobitve
apt update && apt -y upgrade

# 2) uporabnik brez roota
adduser deploy                 # geslo si zapomni
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh && chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys

# 3) utrdi SSH (root login off, gesla off)
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/'        /etc/ssh/sshd_config
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

# 4) požarni zid
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable

# od zdaj naprej:  ssh deploy@<IP>
```

(Dokumentacija: ufw 80/443 bosta za Traefik/ingress; za k3s API 6443 NE
odpiraj javno.)

## C. Namestitev k3s (en node)

```bash
sudo -i
curl -sfL https://get.k3s.io | sh -s - --write-kubeconfig-mode 644
# k3s prinese: containerd, Traefik (ingress), Klipper ServiceLB (LoadBalancer na IP noda)
kubectl get nodes          # node = Ready
```
- **LoadBalancer na enem nodu**: Klipper (k3s privzeto) izpostavi `type:
  LoadBalancer` kar na **javnem IP noda** → MetalLB ne potrebuješ.
- **Shramba**: k3s ima vgrajen **local-path** provisioner → za Postgres
  uporabi `storageClass: local-path` (namesto `longhorn` v manifestu).

## D. Postgres (CNPG) + aplikacija

```bash
# 1) CNPG operator (pripni verzijo, ki jo preveriš na cloudnative-pg.io)
kubectl apply --server-side -f \
  https://raw.githubusercontent.com/cloudnative-pg/cloudnative-pg/release-1.24/releases/cnpg-1.24.0.yaml

# 2) namespace
kubectl apply -f k8s/app/base/namespace.yaml
```

Prilagodi `k8s/cluster/sola-cnpg-cluster.yaml` za EN NODE:
```yaml
spec:
  instances: 1              # en node → 1 instanca (pozneje 3)
  storage:
    size: 5Gi
    storageClass: local-path
```
```bash
kubectl apply -f k8s/cluster/sola-cnpg-cluster.yaml
kubectl -n sola-app get cluster,pods   # sola-db-1 → Running
```

Skrivnosti (NIKOLI v git). Najlažje tako: pripravi datoteko `secrets.env` z
vrsticami `IME=vrednost` za tri ključe:
- `SECRET_KEY` — naključen; generiraj z `python3 -c 'import secrets;print(secrets.token_urlsafe(48))'`
- `DATABASE_URL` — za CNPG: `postgresql://<uporabnik>:<geslo>@sola-db-rw.sola-app.svc:5432/sola`;
  geslo prebereš iz CNPG-jevega secret-a:
  `kubectl -n sola-app get secret sola-db-app -o jsonpath='{.data.uri}' | base64 -d`
- `MAIL_PASSWORD` — SMTP geslo šole

```bash
kubectl -n sola-app create secret generic sola-secrets --from-env-file=secrets.env
```

ConfigMap `sola-config` (v `k8s/app/base/sola-configmap.yaml`) prilagodi za svojo
domeno: `BASE_URL`, `APP_PORT=8002`, `SCHEDULE`, `RAZREDI`, `PROSTORI`.

```bash
# 3) deployment s samo 1 repliko (en node)
sed -i 's/replicas: 3/replicas: 1/' k8s/app/base/sola-deployment.yaml

# 4) objava aplikacije
kubectl apply -k k8s/app/overlays/production-lb   # Service type=LoadBalancer (Klipper → IP noda)
kubectl -n sola-app get pods,svc
```
Slika `mato12345/sola-app:latest` se povleče sama; za svojo kodo v novem
sistemu uporabi `scripts/deploy-prod.sh` (build+push+rollout). Ali naloži
obstoječi `.sql` backup prek `/settings` → Obnova.

## E. DNS, TLS, preverjanje

1. **DNS**: A zapis domene → IP noda (IPv6 po želji).
2. **TLS**: Traefik + cert-manager (Let's Encrypt), ali Cloudflare proxy pred IP.
3. **Health**:
```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<domena>/health   # pričakuj 200
```
4. Prijava: `/auth/login` → `mainadmin / Admin123` (takoj spremeni!) in
   `admin_<oznaka> / admin123`.

## F. Ko dodaš 2. in 3. node (HA)

1. Naroči še 2× Cloud VPS 4 (isti plan), v **isti lokaciji**, naredi
   **privatno mrežo** (Contabo Private Networking) med nodi.
2. Na nodu 1 dobi **join token**:
   `sudo cat /var/lib/rancher/k3s/server/node-token`
3. Na nodu 2/3:
   ```bash
   curl -sfL https://get.k3s.io | K3S_URL=https://<IP-node1>:6443 \
     K3S_TOKEN=<token> sh -
   ```
4. Povečaj: `replicas: 3`, CNPG `instances: 3`; namesti Longhorn (ali uporabi
   privatno mrežo + lokalne diske) za replikacijo; po želji Hetzner/Contabo LB.
5. Namesti **k3s cloud controller** ali pusti Klipper + Floating IP za
   LoadBalancer na več nodih.

## Povzetek »danes«
A (naroči) → B (utrdi) → C (k3s) → D (Postgres+app, 1 instanca/1 replika) →
E (DNS+TLS+health). Ko dela, dodaš node 2 in 3 (F) in preklopiš na 3/3.
